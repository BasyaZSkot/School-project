# MultiMarket

MultiMarket — агрегатор поиска товаров на маркетплейсах с объединением предложений, сравнением цен и мониторингом изменений.

Полный справочник классов, методов и функций приложения: [backend/PROJECT_REFERENCE.md](backend/PROJECT_REFERENCE.md).

## Возможности

- Поиск сейчас включён на Яндекс Маркете; Ozon и Wildberries показываются как временно выключенные, без сетевых запросов.
- Загрузка публичных страниц поиска маркетплейсов в реальном времени.
- Извлечение карточек Product из Schema.org JSON-LD и microdata, если площадка публикует эти данные в HTML.
- Отдельные адаптеры Ozon, Wildberries и Яндекс Маркета с собственными URL и списками разрешённых доменов.
- Диагностика пустой выдачи и HTTP-ограничений отдельно по каждой площадке.
- Сервер возвращает до 200 карточек Яндекс Маркета одним ответом; браузер показывает первые 20, а кнопка раскрывает следующие 20 из полученного списка.
- Карточки товаров с названием, изображением, ценой, площадкой, ссылкой и наличием (если эти поля доступны).
- Отдельная страница для каждой карточки сравнения: предложения всех площадок, цена, описание и характеристики из доступной разметки.
- Аккаунты через OAuth 2.0 Google и Яндекс, профиль и закрытая админ-панель с управлением ролями.
- Единая модель предложения и группировка по GTIN, бренду/модели или нормализованному названию.
- Независимые тайм-ауты источников: сбой одной площадки не отменяет результаты двух других.
- Поддержка разрешённых JSON-фидов как дополнительного, более стабильного источника.
- Локальный мониторинг цены, история, оповещения, CSV-экспорт и русскоязычный интерфейс.
- Графики истории со шкалой цен и дат, выбором периода (7/30/90 дней), минимумом/максимумом и изменением в валюте товара и процентах. Наведение, касание или ползунок показывают конкретную проверку; таблица раскрывает изменения к предыдущей проверке. Расчёт выполняется отдельно по валютам, по последним 500 доступным проверкам.

## Как работает поиск

Сейчас поиск открывает публичные страницы Яндекс Маркета и собирает до 200 доступных карточек. Ozon и Wildberries остаются видимыми в списке площадок, но помечены как временно выключенные и не получают сетевых запросов. API возвращает найденный набор одним ответом; браузер сразу показывает первые 20 товаров, а кнопка «Показать ещё» раскрывает следующие 20 без повторного запроса. Список активных площадок можно изменить через MULTIMARKET_SEARCH_MARKETPLACES в backend/.env.

Парсер не выполняет вход в аккаунт, не использует cookies пользователя, не обращается к закрытым внутренним API, не обходит CAPTCHA и антибот-защиту. Если конкретная страница не содержит читаемых структурированных карточек или площадка отклоняет запрос, результаты этой площадки могут быть пустыми. HTML маркетплейсов меняется и не является стабильным API; для надёжного промышленного потока предпочтительны официальные API или лицензированные фиды.

## Установка

Требуется Python 3.10+.

```bash
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS/Linux:
# source .venv/bin/activate
python -m pip install -r backend/requirements.txt
uvicorn src.parcers.api:app --app-dir backend --reload
```

Открой http://localhost:8000. Документация API: http://localhost:8000/docs.

## Вход и администрирование

Скопируй `backend/.env.example` в `backend/.env`. В Google Cloud создай проект, заполни экран согласия OAuth, затем открой **Google Auth Platform → Clients → Create client → Web application**. Для тестового режима добавь свои аккаунты как test users. В список **Authorized redirect URIs** добавь точный адрес:

```text
http://localhost:8000/auth/google/callback
```

В [Яндекс OAuth](https://yandex.ru/dev/id/doc/ru/register-auth) создай приложение для входа на сторонний сайт, включи доступ к `login:info` и `login:email` и укажи Redirect URI:

```text
http://localhost:8000/auth/yandex/callback
```

Заполни `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` в `.env`. При локальном запуске открывай приложение по `http://localhost:8000`, чтобы домен совпадал с callback. Адреса возврата задаются в `GOOGLE_REDIRECT_URI` и `YANDEX_REDIRECT_URI`; для другого порта или домена используй соответствующий URL и внеси его в настройки OAuth-провайдера. В Google адрес должен совпадать полностью с зарегистрированным. В Yandex укажи схему, хост, порт и путь callback.

Чтобы назначить первого администратора, укажи его email в `MULTIMARKET_ADMIN_EMAILS` до первого входа. Для постоянных окружений задай случайный `MULTIMARKET_SESSION_SECRET` и `MULTIMARKET_COOKIE_SECURE=true` при работе сайта по HTTPS. Файл `.env` игнорируется Git и не должен попадать в коммиты. Официальные инструкции: [Google OAuth для веб-сервера](https://developers.google.com/identity/protocols/oauth2/web-server) и [регистрация приложения Яндекс ID](https://yandex.com/dev/id/doc/en/register-client).

## Дополнительные JSON-фиды

Если есть разрешённый источник, скопируй `backend/.env.example` в `backend/.env` и добавь URL и токены. Настроенный фид используется вместо чтения публичной HTML-страницы для соответствующей площадки; без URL остаётся best-effort поиск по публичной странице. Стандартный формат — JSON с массивом `offers`:

```json
{
  "offers": [
    {
      "id": "sku-123",
      "title": "Product name",
      "price": 1299.5,
      "currency": "RUB",
      "url": "https://marketplace.example/product/sku-123",
      "brand": "Brand",
      "model": "Model",
      "gtin": "4601234567890",
      "in_stock": true,
      "image_url": "https://cdn.example/image.webp"
    }
  ]
}
```

Для WB поддерживается формат записей `products` из WB-примера через `MULTIMARKET_WB_FEED_FORMAT=wb_records`. Значения `salePriceU`, `priceU` и вложенные цены размеров преобразуются из копеек в рубли.

## Фильтры и карточка товара

Дополнительно доступны избранное (`/favorites`), сравнение (`/compare`), личные уведомления (`/notifications`) и синхронизация города/ПВЗ с аккаунтом. Кнопки избранного и сравнения есть в поиске и карточке. Сравнение поддерживает до четырёх товаров и фильтр различий. Варианты с разной памятью, цветом, комплектацией, версией или состоянием не объединяются только по общей модели/GTIN; неизвестные параметры не угадываются. SKU-параметры ссылок и варианты учитываются в идентичности избранного и сравнения; рекламные метки и регион не создают дублей. Продавец показывается, когда доступен в источнике.

По загруженному набору (до 200 товаров) можно фильтровать цену, валюту, площадку, бренд, наличие, оценку и опубликованный срок доставки, а также менять порядок по цене, оценке и сроку. Все условия должны совпадать в одном предложении магазина. Товары без известного срока не попадают в фильтр быстрой доставки. Фильтры и раскрытые результаты сохраняются при возврате из карточки.

«Лучшее предложение» сравнивает варианты одного товара в одной валюте: выбирается минимальная цена с приоритетом подтверждённого наличия, отсутствующие товары исключаются. Доставка в эту цену не включена. Метки «Быстрая доставка» и «Высокая оценка» требуют соответственно опубликованного срока до двух дней и оценки от 4,5 при наличии хотя бы 10 оценок.

В подробностях доступны галерея до 20 фотографий с увеличением, до 100 характеристик с поиском и до 100 переданных площадкой отзывов. Отзывы раскрываются по 5, их можно отбирать по оценке и упорядочивать. При переключении площадки меняются фотографии, описание, параметры и отзывы; противоречивые характеристики магазинов не смешиваются. Для остальных отзывов доступна ссылка на страницу магазина.

Сроки доставки извлекаются из опубликованных условий страницы или разрешённого фида. Для Яндекс Маркета читаются `deliveryInfo` в поиске и `deliveryVariant` из основного блока `snippet-delivery-options` в карточке; даты рекомендаций других товаров не используются. Фильтр «до N дней» сравнивает последнюю дату интервала, а не первую. Текст «завтра» и даты вроде «20–25 ноя» преобразуются в сроки на дату получения страницы; в интерфейсе показываются календарные даты, чтобы сохранённый результат не сдвигался каждый день. Старые результаты поиска без исправленного поля автоматически обновляются.

Данные не привязаны к адресу пользователя: регион показывается, если источник его передал, окончательные сроки и стоимость проверяются в магазине. Если опубликовано только время в пути без подготовки заказа, оно показывается как частичное условие и не используется как полный срок. Истёкшие даты не участвуют в фильтрах и метках быстрой доставки. Неточные или отсутствующие сведения не подменяются придуманными.

В нормализованном фиде поддерживаются `image_urls` (массив HTTPS URL) и `delivery`: `text`, `min_days`, `max_days`, `earliest_date`, `latest_date` (YYYY-MM-DD), `destination`, `cost`, `currency`. Из JSON-LD извлекаются Product.image и Offer.shippingDetails; время подготовки и перевозки складывается только при наличии обоих интервалов в днях. API подробностей возвращает эти поля вместе с отзывами и характеристиками. Полный набор из поиска передаётся странице через sessionStorage, короткая ссылка содержит запасные основные сведения.

Проверка логики каталога: `node --test frontend/tests/*.test.cjs` (Node.js 22+).

## Город доставки и вкладки «О товаре»

На главной странице над строкой поиска находится выбор города с поиском по списку. Выбор сохраняется в localStorage этого браузера; при смене города текущий запрос повторяется с сохранением фильтров. В карточке товара показан выбранный город и есть ссылка на его изменение. Автоматический режим использует регион, который передала площадка.

`GET /api/regions` возвращает локальный список городов. `region_id` передаётся в `/api/search`, `/api/product-details` и разрешённые JSON-фиды. Запросы, анонимные сессии площадок и кэш результатов разделены по региону. Для публичных ссылок Маркета добавляется параметр `lr`, однако он не гарантирует принятие города площадкой: проверяется регион, фактически возвращённый в HTML. Если город не подтверждён, сроки и стоимость доставки не используются, а интерфейс объясняет, что их нужно уточнить в магазине. Проверенное анонимное подключение Маркета может возвращать свой регион по умолчанию даже при выборе другого города; автоматического изменения его настроек аккаунта нет.

Блок «О товаре» оформлен вкладками «Описание» и «Характеристики». В таблице сначала показаны 10 параметров, кнопка раскрывает полный список и поиск по нему. Для Яндекс Маркета полный список и описание дополнительно извлекаются из уже полученного HTML (`AboutFullSpecsListV2` и `AboutDescriptionV2` в data-apiary patch). Переключение вкладок и раскрытие списка не требуют новых запросов к площадке.

## Пункт выдачи: список, адресные подсказки и Яндекс Карты

Для смены города и ПВЗ есть отдельная страница `/delivery` — «Доставка». Ссылки на неё доступны на главной, в карточке и аккаунте. На странице видны город и сохранённые пункты трёх площадок; кнопки «Выбрать» и «Изменить» переводят к поиску нужной площадки. Город сохраняется сразу, пункт — кнопкой подтверждения; возврат ведёт к исходному товару или поиску. Параметр `return_to` допускает только локальные страницы поиска и товара. Можно начать вводить улицу и дом, выбрать адрес из подсказок и увидеть ПВЗ рядом, либо выбрать сам пункт в списке или на карте. Карта и список синхронизированы; после перемещения карты кнопка «Найти в этой области» загружает пункты вокруг нового центра. Список раскрывается по 20. Выбор сохраняется в этом браузере отдельно для каждого сочетания города и площадки; его можно изменить или удалить. Произвольный введённый адрес не сохраняется как якобы существующий ПВЗ.

Карта использует JavaScript API Яндекс Карт 2.1. Добавьте в `backend/.env` ключ `YANDEX_MAPS_API_KEY` для **JavaScript API и HTTP Геокодера**, а также `YANDEX_SUGGEST_API_KEY` для **Геосаджеста**. Это отдельные ключи из [кабинета разработчика](https://developer.tech.yandex.ru/), ключи OAuth не подходят. Для браузерного ключа настройте ограничения по доменам сайта, включая `localhost` и `127.0.0.1` при локальной разработке; для серверного Геосаджеста учитывайте IP сервера. Файл `.env` не включается в Git. Ключ карты по назначению передаётся браузеру через `/api/map-config`; ключ Геосаджеста остаётся на сервере. При добавлении ключей в `.env` они подхватываются при следующем открытии формы, без перезапуска сервера. После изменения уже загруженного ключа карты обновите страницу.

Когда оба ключа настроены, адресные подсказки приходят из Геосаджеста; координаты выбранного адреса определяет Геокодер JS API. Leaflet не используется. Пока ключей нет, список ПВЗ и адресные подсказки Photon доступны, а вместо карты показано понятное сообщение. Ошибка настроенного Геосаджеста не маскируется переключением на другой источник.

Пункты и постаматы Ozon, Wildberries и Яндекс Маркета берутся из открытых данных OpenStreetMap через [Photon](https://github.com/komoot/photon). Это справочник мест, а не API оформления заказа: список может быть неполным, отсутствие номера дома явно отмечено; доступность конкретного товара, срок и стоимость в этом пункте подтвердит площадка при оформлении. Выбор в MultiMarket не меняет адрес в аккаунте маркетплейса и не пересчитывает его опубликованные сроки. Метки площадок проверяются по названию и типу объекта, координаты — по радиусу поиска. За один запрос загружается до 50 результатов в радиусе до 6 км, при ограничении предлагается уточнить область. Атрибуция OSM и Яндекса показана в форме.

`GET /api/pickup-points?region_id=213&marketplace=Ozon` возвращает пункты вокруг центра города; необязательные `lat`, `lon`, `radius` позволяют искать в другой области рядом с выбранным городом. `GET /api/address-suggestions?region_id=213&q=Тверская` возвращает адресные подсказки. Photon-запросы сериализованы с интервалом не менее секунды, одинаковые запросы объединяются, города кэшируются на неделю, пункты на 6 часов, адресные подсказки Photon на час. Результаты Яндекса не кэшируются и не сохраняются в локальную базу. Публичный Photon предназначен для небольшого трафика без гарантии доступности; для развёртывания с нагрузкой укажите собственный сервер через `MULTIMARKET_PHOTON_URL`. Документация: [подключение Яндекс Карт](https://yandex.ru/dev/jsapi-v2-1/doc/ru/v2-1/dg/concepts/load), [Геосаджест](https://yandex.ru/maps-api/docs/suggest-api/request.html).

## Мониторинг цен

Из карточки предложения нажми «Следить за ценой». По умолчанию товар проверяется раз в час; допустимый интервал — от 15 минут до 7 дней. История хранится в SQLite (`backend/data/multimarket.sqlite3`). В «Моих товарах» можно настроить целевую цену с валютой либо процент изменения относительно предыдущей проверки, направление изменения и каналы. Целевая цена срабатывает при достижении и не повторяется на каждом опросе; валюты не смешиваются. События доступны на странице «Уведомления», внешняя отправка выполняется только по личным подтверждённым каналам с повторными попытками. Если источник не вернул предложение с тем же URL, новая точка цены не создаётся.

## Почта, восстановление доступа и Telegram

Локальные аккаунты поддерживают подтверждение email и восстановление пароля через SMTP. В базе хранятся только хеши одноразовых токенов; сроки — 24 часа для подтверждения и 30 минут для восстановления. Сброс пароля инвалидирует прежние сеансы. Цена по Email отправляется только на подтверждённый адрес владельца. Для Telegram пользователь подтверждает привязку через одноразовую ссылку и личный чат; общий chat ID для личных уведомлений не используется. Пока SMTP/бот не настроены, работают функции сайта, а недоступные внешние каналы явно обозначены.

Пошаговая инструкция с переменными окружения: **[SETUP_ACCOUNTS_NOTIFICATIONS.md](SETUP_ACCOUNTS_NOTIFICATIONS.md)**. Реальные секреты добавляются только в `backend/.env` и не включаются в Git. Список сравнения остаётся локальным; избранное и доставка синхронизируются через закрытые API пользователя.

## Запросы отдельных площадок

Отправка публичных запросов разделена: `backend/src/parcers/wb_requests.py`, `ozon_requests.py` и `ym_requests.py`. Каждый адаптер вызывает свой `fetch_public_page`; у каждой площадки собственные клиенты, cookies, кэш и состояние повторов, дополнительно разделённые по регионам. Способ загрузки WB можно менять в `wb_requests.py`, не меняя Ozon и Яндекс Маркет. Сам вызов `await client.get(url)` находится в функции `send_get(client, url)` каждого из этих трёх файлов. Здесь можно отдельно менять параметры GET-запроса конкретной площадки. Общий `transport.py` вызывает переданную функцию и сохраняет таймауты, повторы и обработку ответа. Проверка домена после перенаправления и передача выбранного региона сохранены. Подключаемые JSON-фиды используют прежний отдельный механизм.

## Передача списка Item из WB-парсера на сайт

Верните список объектов `Item` из `backend/src/parcers/wb_items.py`, функция `async def fetch_items(query, limit=200)`. `query` - текст поиска на сайте. Возвращать нужно сами объекты, а не `print(items)`, строку или Excel-файл. Для синхронного парсера вызывайте его через `await asyncio.to_thread(parse, query)`, чтобы не блокировать сервер.

```python
async def fetch_items(query: str, limit: int = 200) -> list:
    items = ...  # результат вашего парсера: list[Item]
    return items[:min(limit, 200)]
```

После подключения парсера добавьте в `backend/.env` и перезапустите сервер:

```env
MULTIMARKET_WB_SOURCE=items
MULTIMARKET_SEARCH_MARKETPLACES=Яндекс Маркет,Wildberries
```

В этом режиме `salePriceU`/`priceU` объектов Item считаются рублями: 3328.0 отображается как 3328 рублей. Если их нет, `sizes[].price` читается в копейках. Для существующих сырых JSON-фидов прежний режим копеек сохранён. Цена с WB-кошельком не заменяет обычную цену товара. Карточка получает ссылку по артикулу, бренд, продавца, наличие, рейтинг, число оценок, фотографии, описание и доступные характеристики. Неизвестные сроки доставки и тексты отзывов не выдумываются. До подключения парсера функция возвращает пустой список. Новая папка парсера с дефисами в названии автоматически не импортируется.
