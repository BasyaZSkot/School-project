# MultiMarket

MultiMarket — агрегатор поиска товаров на маркетплейсах с объединением предложений, сравнением цен и мониторингом изменений.

Полный справочник классов, методов и функций приложения: [backend/PROJECT_REFERENCE.md](backend/PROJECT_REFERENCE.md).

## Возможности

- Поиск сейчас включён на Яндекс Маркете; Ozon и Wildberries показываются как временно выключенные, без сетевых запросов.
- Загрузка публичных страниц поиска маркетплейсов в реальном времени.
- Извлечение карточек Product из Schema.org JSON-LD и microdata, если площадка публикует эти данные в HTML.
- Отдельные адаптеры Ozon, Wildberries и Яндекс Маркета с собственными URL и списками разрешённых доменов.
- Диагностика пустой выдачи и HTTP-ограничений отдельно по каждой площадке.
- Сервер возвращает до 200 карточек Яндекс Маркета одним ответом; браузер показывает первые 20, а кнопка раскрывает следующие 20 из полученного списка.
- Карточки товаров с названием, изображением, ценой, площадкой, ссылкой и наличием (если эти поля доступны).
- Отдельная страница для каждой карточки сравнения: предложения всех площадок, цена, описание и характеристики из доступной разметки.
- Аккаунты через OAuth 2.0 Google и Яндекс, профиль и закрытая админ-панель с управлением ролями.
- Единая модель предложения и группировка по GTIN, бренду/модели или нормализованному названию.
- Независимые тайм-ауты источников: сбой одной площадки не отменяет результаты двух других.
- Поддержка разрешённых JSON-фидов как дополнительного, более стабильного источника.
- Локальный мониторинг цены, история, оповещения, CSV-экспорт и русскоязычный интерфейс.

## Как работает поиск

Сейчас поиск открывает публичные страницы Яндекс Маркета и собирает до 200 доступных карточек. Ozon и Wildberries остаются видимыми в списке площадок, но помечены как временно выключенные и не получают сетевых запросов. API возвращает найденный набор одним ответом; браузер сразу показывает первые 20 товаров, а кнопка «Показать ещё» раскрывает следующие 20 без повторного запроса. Список активных площадок можно изменить через MULTIMARKET_SEARCH_MARKETPLACES в backend/.env.

Парсер не выполняет вход в аккаунт, не использует cookies пользователя, не обращается к закрытым внутренним API, не обходит CAPTCHA и антибот-защиту. Если конкретная страница не содержит читаемых структурированных карточек или площадка отклоняет запрос, результаты этой площадки могут быть пустыми. HTML маркетплейсов меняется и не является стабильным API; для надёжного промышленного потока предпочтительны официальные API или лицензированные фиды.

## Установка

Требуется Python 3.10+.

```bash
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS/Linux:
# source .venv/bin/activate
python -m pip install -r backend/requirements.txt
uvicorn src.parcers.api:app --app-dir backend --reload
```

Открой http://localhost:8000. Документация API: http://localhost:8000/docs.

## Вход и администрирование

Скопируй `backend/.env.example` в `backend/.env`. В Google Cloud создай проект, заполни экран согласия OAuth, затем открой **Google Auth Platform → Clients → Create client → Web application**. Для тестового режима добавь свои аккаунты как test users. В список **Authorized redirect URIs** добавь точный адрес:

```text
http://localhost:8000/auth/google/callback
```

В [Яндекс OAuth](https://yandex.ru/dev/id/doc/ru/register-auth) создай приложение для входа на сторонний сайт, включи доступ к `login:info` и `login:email` и укажи Redirect URI:

```text
http://localhost:8000/auth/yandex/callback
```

Заполни `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET` в `.env`. При локальном запуске открывай приложение по `http://localhost:8000`, чтобы домен совпадал с callback. Адреса возврата задаются в `GOOGLE_REDIRECT_URI` и `YANDEX_REDIRECT_URI`; для другого порта или домена используй соответствующий URL и внеси его в настройки OAuth-провайдера. В Google адрес должен совпадать полностью с зарегистрированным. В Yandex укажи схему, хост, порт и путь callback.

Чтобы назначить первого администратора, укажи его email в `MULTIMARKET_ADMIN_EMAILS` до первого входа. Для постоянных окружений задай случайный `MULTIMARKET_SESSION_SECRET` и `MULTIMARKET_COOKIE_SECURE=true` при работе сайта по HTTPS. Файл `.env` игнорируется Git и не должен попадать в коммиты. Официальные инструкции: [Google OAuth для веб-сервера](https://developers.google.com/identity/protocols/oauth2/web-server) и [регистрация приложения Яндекс ID](https://yandex.com/dev/id/doc/en/register-client).

## Дополнительные JSON-фиды

Если есть разрешённый источник, скопируй `backend/.env.example` в `backend/.env` и добавь URL и токены. Настроенный фид используется вместо чтения публичной HTML-страницы для соответствующей площадки; без URL остаётся best-effort поиск по публичной странице. Стандартный формат — JSON с массивом `offers`:

```json
{
  "offers": [
    {
      "id": "sku-123",
      "title": "Product name",
      "price": 1299.5,
      "currency": "RUB",
      "url": "https://marketplace.example/product/sku-123",
      "brand": "Brand",
      "model": "Model",
      "gtin": "4601234567890",
      "in_stock": true,
      "image_url": "https://cdn.example/image.webp"
    }
  ]
}
```

Для WB поддерживается формат записей `products` из WB-примера через `MULTIMARKET_WB_FEED_FORMAT=wb_records`. Значения `salePriceU`, `priceU` и вложенные цены размеров преобразуются из копеек в рубли.

## Фильтры и карточка товара

По загруженному набору (до 200 товаров) можно фильтровать цену, валюту, площадку, бренд, наличие, оценку и опубликованный срок доставки, а также менять порядок по цене, оценке и сроку. Все условия должны совпадать в одном предложении магазина. Товары без известного срока не попадают в фильтр быстрой доставки. Фильтры и раскрытые результаты сохраняются при возврате из карточки.

«Лучшее предложение» сравнивает варианты одного товара в одной валюте: выбирается минимальная цена с приоритетом подтверждённого наличия, отсутствующие товары исключаются. Доставка в эту цену не включена. Метки «Быстрая доставка» и «Высокая оценка» требуют соответственно опубликованного срока до двух дней и оценки от 4,5 при наличии хотя бы 10 оценок.

В подробностях доступны галерея до 20 фотографий с увеличением, до 100 характеристик с поиском и до 100 переданных площадкой отзывов. Отзывы раскрываются по 5, их можно отбирать по оценке и упорядочивать. При переключении площадки меняются фотографии, описание, параметры и отзывы; противоречивые характеристики магазинов не смешиваются. Для остальных отзывов доступна ссылка на страницу магазина.

Сроки доставки извлекаются из опубликованных условий страницы или разрешённого фида. Данные не привязаны к адресу пользователя: регион показывается, если источник его передал, окончательные сроки и стоимость проверяются в магазине. Если опубликовано только время в пути без подготовки заказа, оно показывается как частичное условие и не используется как полный срок. Неточные или отсутствующие сведения не подменяются придуманными.

В нормализованном фиде поддерживаются `image_urls` (массив HTTPS URL) и `delivery`: `text`, `min_days`, `max_days`, `earliest_date`, `latest_date` (YYYY-MM-DD), `destination`, `cost`, `currency`. Из JSON-LD извлекаются Product.image и Offer.shippingDetails; время подготовки и перевозки складывается только при наличии обоих интервалов в днях. API подробностей возвращает эти поля вместе с отзывами и характеристиками. Полный набор из поиска передаётся странице через sessionStorage, короткая ссылка содержит запасные основные сведения.

Проверка логики каталога: `node --test frontend/tests/*.test.cjs` (Node.js 22+).

## Мониторинг цен

Из карточки предложения нажми «Следить за ценой». По умолчанию товар проверяется раз в час; допустимый интервал — от 15 минут до 7 дней. История хранится в SQLite (`backend/data/multimarket.sqlite3`). Изменение цены на 10% и более записывается как alert. Если источник не вернул предложение с тем же URL, новая точка цены не создаётся.
