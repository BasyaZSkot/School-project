
# Принцип работы Wildberies

При переходе по стандартной ссылке поиска (например, `https://www.wildberries.ru/catalog/0/search.aspx?search=...`) клиентская часть сайта отправляет фоновый GET-запрос для получения данных:

```text
https://www.wildberries.ru/__internal/u-search/exactmatch/ru/common/v18/search?ab_testing=false&appType=1&curr=rub&dest=1259570991&hide_vflags=4294967296&inheritFilters=true&lang=ru&locale=ru&query=ВАШ_ЗАПРОС&resultset=catalog&sort=popular&spp=30&suppressSpellcheck=false
```

В ответ сервер возвращает готовый структурированный JSON, содержащий все необходимые характеристики товаров из поисковой выдачи. Подставляя нужный текст (с учетом URL-кодирования) в параметр `query=...`, мы можем получать чистые данные для базы нашего агрегатора.

## Структура обрабатываемых данных JSON

Для работы с полученным JSON используется скрипт на Python (`parse_wb_json`), который извлекает ключевые параметры товара по следующим правилам:

*   **Расположение товаров**: Вся информация о товарах из поисковой выдачи находится в корневом массиве `products`.
*   **Идентификаторы (SKU)**: Артикул (SKU) товара хранится в поле `id` (например, `299871801`). 
*   **Ссылки на товар**: Зная этот ID, можно легко формировать прямую ссылку на товар в формате `https://www.wildberries.ru/catalog/{id}/detail.aspx`.
*   **Название и бренд**: Название товара лежит в поле `name`, а бренд — в поле `brand`.
*   **Особенности парсинга цен**: Цены лежат в массиве `sizes` внутри объекта `price`. **Важно:** значения цен во внутреннем API передаются умноженными на 100. Для получения реальной стоимости в рублях их необходимо делить на 100. 
*   **Скидки**: Оригинальная цена (без скидки) находится в поле `basic`, а актуальная цена со скидкой — в поле `product`.
*   **Рейтинг и отзывы**: Рейтинг товара передается в поле `reviewRating`, а количество оставленных отзывов — в поле `feedbacks`.
*   **Складские остатки**: Информацию об общем количестве доступного товара можно получить из поля `totalQuantity`.

# Парсер поисковой выдачи Ozon (Внутреннее API)

Данный модуль разработан для агрегатора маркетплейсов с целью сбора данных о товарах, ценах и рейтингах для последующего сравнения.

В отличие от большинства других площадок, Ozon обладает сложной системой защиты от ботов (Cloudflare, WAF) и динамическим рендерингом (SPA). Классический парсинг HTML-кода здесь не работает, так как сервер возвращает пустой каркас. Решением является перехват и анализ фоновых GET-запросов к внутреннему API маркетплейса.

## Принцип работы

При поиске товаров клиентская часть сайта отправляет запрос к API (например, `https://www.ozon.ru/api/entrypoint-api.bx/page/json/v2...`). Сервер в ответ отдает структурированные данные о товарах в формате JSON. Именно эти ответы перехватываются и обрабатываются нашим скриптом.

## Особенности обработки данных (JSON)

Из-за сложной архитектуры маркетплейса скрипт на Python (`parse_ozon_json`) извлекает информацию по особым правилам:

* **Двойной парсинг (JSON в JSON)**: Все данные о товарах находятся внутри корневого блока `widgetStates`. Сами данные виджетов (например, сетки товаров) лежат в виде строки, которая также является JSON-объектом. Её необходимо декодировать отдельно (`json.loads()`).
* **Поиск нужного виджета**: Товары чаще всего находятся в виджетах, в названии которых есть `tileGridDesktop` или `searchResults`.

### Сбор характеристик
Информация о конкретном товаре разбита на блоки внутри массива `mainState`:
* **Название**: Извлекается из блока, где `type` равен `textDS`, а `id` равен `name`.
* **Цены**: Находятся в блоке `priceV2`. Текущая цена (со скидкой) и старая цена хранятся внутри массива `price`.
* **Рейтинг и отзывы**: Ищутся в структуре `labelListV2`, часто рядом с иконкой звезды (`ic_s_star_filled_compact`).
* **Остатки**: Данные о наличии товара (например, "117 ед осталось") извлекаются по параметру `textColor` со значением `textAccent`.
* **Идентификаторы и ссылки**: Уникальный артикул (SKU) доступен в полях `sku` и `id`, а относительная ссылка для перехода на страницу товара находится в `action.link`._

## Работа с пагинацией

Ozon использует сложную систему защиты при листании страниц: для перехода на новую страницу требуются специальные секретные токены `search_page_state` и `paginator_token`. 
Наш скрипт не вычисляет их вручную, а автоматически извлекает готовую защищенную ссылку на следующую страницу из корневого поля `nextPage` предыдущего JSON-ответа.

## Рекламные карточки (Трафареты)

Первые 4-8 товаров в поисковой выдаче Ozon часто выкуплены продавцами под рекламу. Они могут не попадать в стандартный виджет `tileGridDesktop`.
Чтобы собрать полные цены для сравнения, парсер дополнительно сканирует `widgetStates` на наличие рекламных блоков, проверяя ключи со словами `sponsored`, `premium`, `adv` или `topAds`. В некоторых случаях самые первые рекламные позиции могут быть вшиты в изначальный HTML-код страницы (SSR), что требует поиска JSON-структуры напрямую в исходном коде страницы через регулярные выражения.

# Парсер поисковой выдачи Яндекс Маркет (Внутреннее API)

Данный модуль разработан в рамках создания проекта по информатике, целью которого является объединение нескольких маркетплейсов в один сайт для сравнения цен и других характеристик.

Парсинг Яндекс Маркета имеет свою специфику из-за гибридного рендеринга и многоуровневой структуры JSON-ответов. Вместо классического парсинга HTML-кода, данный скрипт перехватывает и анализирует фоновые запросы к внутреннему API маркетплейса.

## Принцип работы

При выполнении поиска или переходе по страницам, клиентская часть сайта отправляет запрос к специальному эндпоинту API (через apphost):

```text
https://market.yandex.ru/api/resolve/?r=../../../b2c-shared/src/resolvers/search/resolvePoorRemoteSearchApphost:resolvePoorRemoteSearchApphost
```

В ответ сервер отдает масштабный JSON-объект, содержащий информацию о товарах, медиафайлах, фильтрах и рекламных врезках. Извлекая из него нужные блоки, мы можем получать чистые данные для базы нашего агрегатора без обхода капчи на HTML-страницах.

## Структура обрабатываемых данных JSON

Ответ Яндекс Маркета имеет сложную вложенную структуру. Наш парсер на Python извлекает ключевые параметры товара по следующим правилам:

*   **Расположение товаров**: Все основные карточки из поисковой выдачи находятся в корневом массиве `collections.widgets`.
*   **Название**: Извлекается из блока `product.productPayload.title.value`.
*   **Идентификаторы (SKU)**: Уникальный артикул (для связи товаров в БД) доступен в полях `product.productPayload.cartButton.msku` и `offerParams.oskuId`. 
*   **Ссылки на товар**: Для формирования красивого URL используется поле `offerParams.slug`.
*   **Особенности парсинга цен**: Текущая цена находится в блоке `product.productPayload.price.actualPrice.amount.intPart` (выражена сразу в рублях, валюта указана в `currency`). Старая цена (до скидки) передается в блоке `cartButton.oldPrice`.
*   **Складские остатки**: Информацию об ограниченном количестве (например, "Осталось 2 шт") парсер получает из блока `product.productPayload.signals.lastStock.text.text`.
*   **Рейтинг и отзывы**: Ищутся в структуре `rating` внутри карточки (где доступны средний балл `ratingValue` и количество оценок `ratingCount`).
*   **Медиафайлы**: Картинки лежат в массиве `product.productPayload.gallery.mediaItems`. Также маркетплейс использует глобальный репозиторий `collections.mediaItem`, где изображения хранятся по уникальным хэш-ключам.

## Рекламные карточки (Врезки / Incuts)

В поисковой выдаче Яндекс Маркета часть мест выкуплена продавцами под рекламу. В JSON-ответе они не лежат как обычные элементы `type: "product"` в сетке. 

Для их обработки парсер ищет виджеты с `type: "incut"` (рекламная врезка, например, блок "Скидки недели"). Внутри такой врезки находится массив `snippets`, содержащий рекламные товары с меткой `type: "AD_QUICK"`. Наш скрипт дополнительно сканирует эти врезки и извлекает из них данные (цены, названия, `msku`), чтобы собрать для агрегатора абсолютно все товары, показанные пользователю.
