# MultiMarket

MultiMarket — агрегатор поиска товаров на маркетплейсах с объединением предложений, сравнением цен и мониторингом изменений.

## Возможности

- Одновременный поиск по Ozon, Wildberries и Яндекс Маркету при отправке пользовательского запроса.
- Загрузка публичных страниц поиска маркетплейсов в реальном времени.
- Извлечение карточек Product из Schema.org JSON-LD и microdata, если площадка публикует эти данные в HTML.
- Отдельные адаптеры Ozon, Wildberries и Яндекс Маркета с собственными URL и списками разрешённых доменов.
- Диагностика пустой выдачи и HTTP-ограничений отдельно по каждой площадке.
- Первые 20 карточек товаров показываются сразу; следующие страницы подгружаются кнопкой «Показать ещё 20 товаров».
- Карточки товаров с названием, изображением, ценой, площадкой, ссылкой и наличием (если эти поля доступны).
- Единая модель предложения и группировка по GTIN, бренду/модели или нормализованному названию.
- Независимые тайм-ауты источников: сбой одной площадки не отменяет результаты двух других.
- Поддержка разрешённых JSON-фидов как дополнительного, более стабильного источника.
- Локальный мониторинг цены, история, оповещения, CSV-экспорт и русскоязычный интерфейс.

## Как работает поиск

При отправке запроса сервер параллельно открывает обычные HTTPS-страницы поиска трёх маркетплейсов. API возвращает глобальные страницы товаров по 20 карточек; кнопка «Показать ещё» запрашивает следующую страницу, а результаты объединяются и дедуплицируются между площадками. Пользователь видит состояние «Ищем товары…». После ответа сервер разбирает структурированные карточки Schema.org Product (JSON-LD и microdata) и объединяет предложения. Если HTML доступен, но в нём нет поддерживаемой разметки, интерфейс показывает «Нет карточек»; при HTTP 401/403/429/498 сообщает об ограничении доступа.

Парсер не выполняет вход в аккаунт, не использует cookies пользователя, не обращается к закрытым внутренним API и не решает CAPTCHA. Чтобы реже попадать под блокировки, запросы идут через транспортный слой `backend/src/parcers/transport.py`: заголовки актуального браузера, паузы между запросами к одному сайту, повторы с экспоненциальной задержкой (с учётом `Retry-After`), cookies сессии, которые выдаёт сам сайт, и необязательные прокси, которые вы указываете сами в `MULTIMARKET_PROXY_URLS`. Если площадка всё равно возвращает 401/403/429/498 или страницу капчи, результат помечается как `policy_restricted`. Если конкретная страница не содержит читаемых структурированных карточек или площадка отклоняет запрос, результаты этой площадки могут быть пустыми. HTML маркетплейсов меняется и не является стабильным API; для надёжного промышленного потока предпочтительны официальные API или лицензированные фиды.

## Установка

Требуется Python 3.10+.

```bash
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS/Linux:
# source .venv/bin/activate
python -m pip install -r backend/requirements.txt
uvicorn src.parcers.api:app --app-dir backend --reload
```

Открой http://127.0.0.1:8000. Документация API: http://127.0.0.1:8000/docs.

## Дополнительные JSON-фиды

Если есть разрешённый источник, скопируй `backend/.env.example` в `backend/.env` и добавь URL и токены. Настроенный фид используется вместо чтения публичной HTML-страницы для соответствующей площадки; без URL остаётся best-effort поиск по публичной странице. Стандартный формат — JSON с массивом `offers`:

```json
{
  "offers": [
    {
      "id": "sku-123",
      "title": "Product name",
      "price": 1299.5,
      "currency": "RUB",
      "url": "https://marketplace.example/product/sku-123",
      "brand": "Brand",
      "model": "Model",
      "gtin": "4601234567890",
      "in_stock": true,
      "image_url": "https://cdn.example/image.webp"
    }
  ]
}
```

Для WB поддерживается формат записей `products` из WB-примера через `MULTIMARKET_WB_FEED_FORMAT=wb_records`. Значения `salePriceU`, `priceU` и вложенные цены размеров преобразуются из копеек в рубли.

## Мониторинг цен

Из карточки предложения нажми «Следить за ценой». По умолчанию товар проверяется раз в час; допустимый интервал — от 15 минут до 7 дней. История хранится в SQLite (`backend/data/multimarket.sqlite3`). Изменение цены на 10% и более записывается как alert. Если источник не вернул предложение с тем же URL, новая точка цены не создаётся.
